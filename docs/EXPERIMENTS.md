# 실험과 검증 기록

## 읽는 법

공개 dev 200건은 반복해서 개발에 사용했습니다. 이 문서의 dev Macro F1은 후보 비교용 진단값이며 독립 검증 점수나 숨김 리더보드 추정치가 아닙니다. 서로 다른 GPU 실행의 작은 차이는 모델·batch 수치 변동이 섞일 수 있습니다.

사용자가 확인한 리더보드 점수는 다음과 같습니다.

| 제출 계열 | 같은 계열의 공개 dev 실측 | 이후 사용자 보고 LB |
|---|---:|---:|
| retry-fixed | 0.750347 | 0.6412 |
| robust | 0.768241 | 0.66205 |
| frontier | 0.792236 | **0.6807** |
| sentinel | 0.789962 | 미확인 |

`sentinel`이 LB 0.75를 달성했다는 증거는 없습니다.

모든 행은 고정 Gemma 모델을 실제 호출한 공개 dev 200건 실행입니다. 단계 시간은 모델 초기화를 제외합니다.

| 구성 | Macro F1 | 단계 초 | 정상 응답 | 재시도 | 결정 |

| frontier 대조군 | 0.808552862 | 669.989 | — | 1 | 비교 기준 |
| 동일 기준 재독해 | 0.782879940 | 707.013 | — | 0 | 제외 |
| 조건 대조·근거 우선 facts | 0.775914358 | 721.938 | — | 0 | 제외 |
| 문서 예산 22,000자 | 0.787106404 | 795.055 | — | 1 | 제외 |
| sliding-window만 고정밀 KV | 0.787919421 | 874.140 | 740 | 0 | 제외 |
| 전체 BF16 KV | 0.798617952 | 865.946 | 734 | 0 | 제외 |

## 제품 pass 분리 비교

동일 참조 실행의 자격·절차 결과를 유지하고 제품 pass만 새로 생성했습니다. 아래는 v10–v18 평균 F1입니다.

| 제품 후보 | 제품 F1 | 단계 초 | 재시도 | 결정 |
|---|---:|---:|---:|---|
| 기존 문맥 대조군 | 0.746452005 | 245.844 | 1 | 기준 |
| 제품 항목만으로 기준 축소 | 0.635244929 | 204.063 | 0 | 제외 |
| 조건 대조 + 근거 우선 + 서비스 목록 | 0.722446218 | 288.892 | 2 | 제외 |
| 위 후보 + 단일 SID | 0.723843150 | 249.040 | 0 | 제외 |
| 기존 문맥 + BGE-M3 CSV 후보 | 0.719331903 | 247.451 | 1 | 제외 |

BGE-M3 전처리는 제공 CSV 616행과 공개 공고 200건에 12.97초가 걸렸습니다. 검색 속도와 최종 분류 이득은 별개였으며, 검색 후보가 법적 제품 분류값을 대신할 수 없었습니다.

## 선택 재검토 비교

동일 대조군에서 v1·v9·v19 양성 34건만 재검토했습니다.

| verifier | 결합 Macro F1 | 단계 초 | 선택 양성의 빈 근거 |
|---|---:|---:|---:|
| 기존 verifier | 0.811853085 | 29.805 | 6 |
| 집중 검토 | **0.813268081** | **22.530** | 1 |
| 단일 SID | 0.812474430 | 23.771 | 0 |
| 집중 검토 + 단일 SID | **0.813268081** | **22.436** | 1 |

집중 검토는 v1의 FP를 줄였지만 v9와 v19에서 FP가 각각 1개 늘었습니다. 전체적인 큰 개선으로 해석하지 않고, 이전 reasoning을 노출하지 않는 독립성·속도·근거 품질을 근거로 제한적으로 채택했습니다.

## 최종 동일 ZIP 검증

| 검사 | 결과 |
|---|---|
| 입력 | 공개 1,853건: dev 200 + 공개 test 10 + 제공 무라벨 1,515 + 장문 128 |
| 벽시계 | 6,390.947초, 모델 초기화 포함 |
| dev 200 Macro F1 | 0.789961863 |
| 정상 응답 | 6,901회 |
| 재시도 | 3회, 모두 정상 응답으로 복구 |
| compact 복구 | 1건 |
| 로컬 검사 | 289 PASS |
| 출력 감사 | 49열·ID·원문 근거·정상 응답·fusion 재구성 PASS |
| 환경 | L40S 1장, CPU affinity 7, 공식 라이브러리 버전 |
| 관측 메모리 | 약 1초 간격 최대 55.992 GiB |

OS 모델 page cache는 지우지 않았고 읽기 전용 cgroup 때문에 공식 60 GiB RAM 제한을 강제하지 못했습니다. 메모리는 연속 peak가 아니라 컨테이너 표본입니다.

## 순서 안정성

별도 무라벨 64건에서 문서 배열과 공고 처리 순서를 함께 반전했습니다.

- 6건에서 6개 라벨 변화
- 양성 합집합 28개 중 22개 일치
- 양성 Jaccard 0.785714

선택용 200건 실행과 최종 1,853건 실행은 기본 600개 specialist prompt hash가 모두 같았지만 dev 21건/24라벨이 달랐습니다. 조건부 verifier와 기업 pass는 앞 결과에 따라 호출 집합도 달라졌습니다. `temperature=0`과 seed 고정만으로 완전한 재현성을 주장할 수 없음을 보여줍니다.

## 성능 해석의 한계

1. dev는 반복 개발에 사용되어 독립 검증셋이 아닙니다.
2. 항목별 양성이 적어 한두 건이 Macro F1을 크게 움직입니다.
3. 공개 라벨에는 원문과 meta가 충돌하는 해석 노이즈가 있습니다.
4. GPU kernel과 batching에 따른 출력 변동이 남았습니다.
5. 최종 `sentinel` ZIP의 외부 평가 점수는 확인되지 않았습니다.
